== Your Company: Acme Inc.

You are a platform engineer at Acme Inc., a financial services company. Your team manages three Java applications:

[cols="2,1,3",options="header"]
|===
| Application | Risk | Description
| `wire-transfer-svc` | *High* | Customer-facing wire transfer processing service. Subject to PCI-DSS and SOX compliance. Downtime or security incidents have direct business impact.
| `benefits-mgmt-app` | *Low* | Internal employee benefits enrollment application. Used by HR during enrollment periods. Not customer-facing; brief downtime is tolerable.
| `report-generator-app` | *Low* | Internal scheduled report generation service. Runs batch jobs for compliance and analytics. No real-time availability requirements.
|===

All three applications are stored in your GitLab instance under the `acme-{guid}` group. Each has intentionally outdated dependencies with known CVEs — that is the point.

=== Lightwell Network (Simulated)

The Lightwell Network publishes remediated, signed builds of open source components — the `.rhlw-NNNNN` versions you read about in Module 0. In a production environment, these would be fetched from `packages.redhat.com` with an active Lightwell subscription.

For this lab, a *simulated* Lightwell repository is hosted in your dedicated Nexus instance. It contains the same artifact structure as the real Lightwell repository — Maven metadata, POMs, and JARs with `.rhlw` version suffixes — so the automation behaves identically. Nexus also serves as a Maven build cache and an OCI container registry for your built images.

* *Quick Win (Path 1):* Renovate watches this repository for new `.rhlw` versions and creates merge requests.
* *Full AI (Path 2):* Nexus fires an event when a new artifact arrives, triggering the Automation Orchestrator workflow.

=== GitLab

Source code for your three Acme applications. Each app has a `pom.xml` with vulnerable dependencies and a `renovate.json` that configures the Lightwell preset.

* *Quick Win (Path 1):* Renovate creates merge requests here. Merging triggers the CI pipeline.
* *Full AI (Path 2):* AI agents create merge requests here. Low-risk ones are auto-approved; high-risk ones wait for you.

=== Renovate Operator

A dependency update tool that creates merge requests when it finds newer versions. Installed at the cluster level; you trigger scans by creating `RenovateJob` custom resources.

* *Quick Win (Path 1):* You create a RenovateJob and watch it generate merge requests.
* *Full AI (Path 2):* Not used — the AI agents handle remediation instead.

=== Tekton Pipelines (CI)

Compiles the application, generates an SBOM, signs the container image, and pushes it to the Nexus OCI registry. Pipelines trigger automatically when a merge request is merged in GitLab.

* *Both paths:* Tekton builds the patched application after you (or the AI) approve a merge request.

=== ArgoCD (CD)

Detects new container images and deploys them to the target environment.

NOTE: In this lab, ArgoCD deploys straight to production. Real-world customers typically configure multiple stages — test, staging, production — each with its own sync policy and approval gate.

* *Both paths:* ArgoCD deploys the newly built image to production after the pipeline completes.

=== Trusted Profile Analyzer (TPA)

Stores and queries SBOMs generated by your builds. Each participant has their own dedicated TPA instance, so you only see data for your own applications.

* *Quick Win (Path 1):* You compare SBOMs after the build to confirm the fix landed.
* *Full AI (Path 2):* The orchestrator actively queries TPA to find which applications are affected by a CVE.

=== ServiceNow (Simulated)

A lightweight mock of ServiceNow's ITSM interface. Provides an audit trail from detection through deployment.

* *Quick Win (Path 1):* Not used.
* *Full AI (Path 2):* The Automation Orchestrator opens a ticket at the start and updates it at every stage — TPA analysis, AI assessment, MR creation, build, deploy, and closure.

=== Automation Orchestrator

Drives the full automation workflow. Receives events from Nexus, dispatches queries to TPA, hands off to AI agents, and tracks the entire flow through ServiceNow.

* *Quick Win (Path 1):* Not used.
* *Full AI (Path 2):* Orchestrates the entire remediation pipeline end to end.
