# Module 01 — Patch Ingestion: From Lightwell to Artifactory to Ansible

## Brief Overview

Participants step into the role of Dinesh, a platform engineer who arrives to find that Lightwell has already processed 298 patches across 29 applications overnight. This module orients participants to the pre-deployed environment, introduces the Lightwell dashboard, and traces the automated ingestion pipeline from Lightwell patch delivery into JFrog Artifactory through to the Event-Driven Ansible trigger. By the end of this module, participants understand how new patches enter the remediation pipeline and where the automated flow hands off to human review.

## Audience and Time

- **Target persona:** Platform engineers and security-focused operations engineers with intermediate OpenShift and CI/CD experience
- **Prerequisites for this module:** Basic familiarity with OpenShift namespaces and console navigation; conceptual understanding of CVEs and patch workflows
- **Estimated duration:** 20 minutes

## Learning Objectives

- Explore the Lightwell dashboard to interpret overnight patch processing results and distinguish auto-merged patches from items flagged for review
- Navigate the Lightwell dashboard to identify high-risk items queued for manual assessment
- Observe how a new patch arrival in JFrog Artifactory triggers an Event-Driven Ansible workflow
- Analyze the patch ingestion pipeline from Lightwell delivery through Artifactory to the EDA handoff point

## Detailed Steps

1. Open the Lightwell dashboard using the URL provided in the lab environment details.
2. Observe the summary panel showing 298 patches processed across 29 applications since the overnight batch run.
3. Locate the "Auto-Merged" history view and review several auto-merged patches to understand what criteria qualified them for safe automatic merging.
4. Switch to the "Flagged for Review" queue and note the number of high-risk items awaiting manual assessment.
5. Select one flagged item and review the summary fields: CVE identifier, affected application, risk tier, and the reason the Deep Agent escalated it for human review.
6. Navigate to the JFrog Artifactory console using the provided URL.
7. Browse to the repository that receives Lightwell patch bundles and identify the most recent bundle artifact.
8. Return to the Lightwell dashboard and observe that the ingestion of each bundle into Artifactory corresponds to a pipeline trigger event.
9. Open the Event-Driven Ansible console and navigate to the active rulebook activations.
10. Locate the rulebook that monitors Artifactory for new patch bundle arrivals and verify that it is in a running state.
11. Review the event log to find the most recent trigger event generated by the overnight patch delivery and note the timestamp and payload fields.
12. Observe that the triggered workflow passes patch metadata to the next stage of the pipeline (Trusted Profile Analyzer).

## Key Takeaways

- Lightwell processes patches continuously; participants enter at the "morning review" state rather than a clean install
- The Lightwell dashboard separates safe auto-merged patches from high-risk items requiring human judgment
- JFrog Artifactory acts as the landing zone for Lightwell patch bundles and the origin of the EDA trigger event
- Event-Driven Ansible provides the event-driven glue that connects patch delivery in Artifactory to downstream analysis and remediation steps

## Infrastructure Notes

- The Lightwell dashboard, JFrog Artifactory instance, and Event-Driven Ansible rulebook activations are all pre-deployed and pre-configured; participants do not install or configure them in this module
- The overnight patch state (298 patches, 29 applications) is seeded by pre-provisioning automation — participants observe it as a starting condition
