# Module 03 — AI-Assisted Remediation: Reviewing and Approving Patches

## Brief Overview

Armed with TPA's environmental impact findings, the Lightwell Deep Agent has generated merge requests for each high-risk patch and routed them to the human review queue. This module places participants in the expert reviewer role: they examine the Deep Agent's risk rationale, inspect the AI-generated code changes in GitLab, evaluate whether the proposed merge requests are safe to approve, and complete the approval workflow. This is the critical human-in-the-loop decision point that gates high-risk patches before they enter the build pipeline.

## Audience and Time

- **Target persona:** Platform engineers and security-focused operations engineers with intermediate OpenShift and CI/CD experience
- **Prerequisites for this module:** Completion of Modules 01 and 02; basic familiarity with merge request review in a Git-based workflow
- **Estimated duration:** 25 minutes

## Learning Objectives

- Explore the Lightwell Deep Agent's risk assessment rationale for each patch flagged for human review
- Analyze AI-generated merge requests in GitLab to evaluate the proposed code and dependency changes
- Verify that the Deep Agent's recommended remediation aligns with the CVE impact scope identified in TPA
- Demonstrate the approval workflow for high-risk patches, routing approved items into the build pipeline
- Observe how the Deep Agent handles patches that participants reject or request changes on

## Lab Structure

| Section | Title | Duration |
|---------|-------|----------|
| 1 | Reviewing Deep Agent Risk Assessments | 7 min |

| 3 | Approving Patches and Submitting for Build | 8 min |

## Detailed Steps

1. Return to the Lightwell dashboard and open the "Flagged for Review" queue.
2. Select the first high-risk item and open its Deep Agent assessment panel.
3. Read the Deep Agent's risk rationale, including the CVE reference, the TPA-assigned risk tier, the affected application, and the recommended remediation action.
4. Note the confidence score the Deep Agent has assigned to its merge request recommendation.
5. Click the link to the AI-generated merge request in GitLab to open it in a new tab.
6. Review the merge request description generated by the Deep Agent, which summarizes the patch, the vulnerability it addresses, and the change scope.
7. Examine the diff view to inspect the specific dependency version changes or code modifications proposed by the Deep Agent.
8. Cross-reference the changed package versions against the fix version identified in TPA's CVE detail view from Module 02 to confirm they match.
9. Review the merge request pipeline status to confirm that automated pre-checks (linting, unit tests) have passed.
10. Return to the Lightwell dashboard and use the approval action to mark this patch as approved for build.
11. Repeat the review and approval workflow for a second high-risk item in the queue.
12. For a third item, use the "Request Changes" action in the Lightwell dashboard to simulate the rejection path, and observe how the Deep Agent records the reviewer's decision.
13. Confirm that approved items have moved from the "Flagged for Review" queue into the "Approved — Pending Build" state.

## Key Takeaways

- The Lightwell Deep Agent generates merge requests automatically and applies a confidence-scored risk rationale, reducing the effort required for expert review
- Human reviewers validate the Deep Agent's reasoning against TPA impact data before approving high-risk changes — this is the intentional human-in-the-loop gate
- GitLab serves as the merge request target; participants review real diff content, not synthetic summaries
- Approved patches transition immediately into the build pipeline; rejected items are recorded with the reviewer's decision and do not advance
- The Deep Agent's behavior on rejection demonstrates that the system supports iterative human feedback, not just binary approve/deny

## Infrastructure Notes

- OpenShift AI is pre-deployed with Deep Agent skills pre-configured; participants do not set up or tune the Deep Agent in this module
- GitLab repositories are pre-populated with sample application source code; the merge requests visible in the review queue were generated during pre-provisioning to simulate overnight Deep Agent activity
