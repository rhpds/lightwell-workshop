# Module 04 — Build, Deploy, and Close the Loop

## Brief Overview

With patches approved in Module 03, the final module traces the end-to-end path from build through multi-cluster deployment to automated ticket resolution. Participants observe the Trusted Software Factory compile, sign, and verify patched container images, then watch Red Hat Advanced Cluster Management and OpenShift GitOps propagate those images across the fleet. The module closes by verifying that ServiceNow tickets tied to the resolved CVEs are automatically updated and closed — demonstrating the full remediation loop from patch ingestion to ITSM closure.

## Audience and Time

- **Target persona:** Platform engineers and security-focused operations engineers with intermediate OpenShift and CI/CD experience
- **Prerequisites for this module:** Completion of Modules 01–03; familiarity with CI/CD pipeline concepts and basic GitOps principles
- **Estimated duration:** 25 minutes

## Learning Objectives

- Observe the Trusted Software Factory build, sign, and verify pipeline processing an approved patch
- Monitor pipeline stage transitions to verify that image signing and attestation complete successfully
- Deploy patched container images across a multi-cluster fleet using Red Hat Advanced Cluster Management
- Observe OpenShift GitOps reconcile the updated image references across target clusters
- Verify end-to-end remediation closure by confirming rollout status and checking that affected CVEs are no longer reported in TPA
- Observe automated ServiceNow ticket resolution triggered by successful deployment and verification

## Detailed Steps

1. Navigate to the Trusted Software Factory pipeline console using the URL provided in the lab environment details.
2. Locate the pipeline run that was triggered when the approved patches transitioned to the "Approved — Pending Build" state in Module 03.
3. Review the pipeline stage list: source fetch, build, image scan, sign, and attestation generation.
4. Monitor the pipeline run as it progresses through each stage and observe any stage-level logs that confirm the image has been signed by the Trusted Software Factory signing service.
5. Once the pipeline completes, locate the signed image artifact in the registry and confirm that the signing attestation is present.
6. Open the Red Hat Advanced Cluster Management console and navigate to the application topology view for one of the affected applications.
7. Observe the current deployed image version across the managed cluster fleet.
8. Navigate to the OpenShift GitOps (ArgoCD) console and locate the application whose image reference was updated by the Trusted Software Factory pipeline.
9. Trigger a manual sync or observe an in-progress automatic sync, and watch GitOps reconcile the updated image reference across the target clusters.
10. Return to RHACM and verify that the cluster fleet now reports the patched image version for the affected application.
11. Navigate to TPA and re-run the impact scope query for the CVE addressed by this patch; verify that the affected application no longer appears in the impact list.
12. Open the ServiceNow sandbox console using the provided URL and locate the incident ticket associated with the CVE remediated in this module.
13. Observe that the ticket status has been automatically updated to "Resolved" and review the resolution note generated by the Lightwell integration, which records the patch ID, the approved merge request, and the deployment timestamp.
14. Return to the Lightwell dashboard and confirm that the remediated item has moved from the "Approved — Pending Build" state to "Closed."

## Key Takeaways

- The Trusted Software Factory provides a governed build path that includes image signing and attestation, ensuring that only verified artifacts reach the deployment pipeline
- RHACM and OpenShift GitOps together provide consistent, policy-driven image rollout across a multi-cluster fleet — participants observe the GitOps reconciliation loop in real time
- TPA re-verification after deployment confirms that the remediation was effective and closes the analytical loop
- Automated ServiceNow ticket resolution is the final stage of the end-to-end pipeline, providing ITSM closure without manual intervention
- The complete flow — from overnight patch delivery through Artifactory, EDA, TPA, Deep Agent review, TSF build, GitOps deployment, and ServiceNow closure — demonstrates how Lightwell compresses a weeks-long manual process into a continuous, policy-driven operation

## Infrastructure Notes

- The Trusted Software Factory pipeline, RHACM managed cluster fleet, OpenShift GitOps instance, and ServiceNow integration are all pre-deployed and pre-wired; participants observe and verify pipeline outputs rather than configuring the toolchain
- The ServiceNow sandbox is pre-wired with incident tickets seeded during pre-provisioning to correspond to the overnight CVE batch
